# 1,
1. run_episode 是最基础的执行单元，负责实际的环境交互
# 训练时 (training_mode=True)：
- 会更新策略
- 会保存状态摘要

# 测试时 (training_mode=False)：
- 不更新策略
- 只收集性能数据

2. run_test 在特定对抗比例下执行多个测试episode

3. run_test_suite 是最高层的测试管理器，负责：
    管理不同算法的测试
    处理不同的对抗比例
    特殊处理BELIEF_QMIX算法
    两种模式
        # BELIEF_QMIX模式：
        - 直接使用当前控制器
        - 只测试一种配置
        # 其他算法模式：
        - 测试多个算法
        - 测试多个对抗比例


# 2，代码逻辑
对抗性智能体的选择机制：
    使用信念机制（Belief Mechanism）来动态确定哪些智能体是对抗性的
    每个智能体都有一个信念值（belief value），范围在0-1之间
    当信念值超过阈值（默认0.6）时，该智能体被认为是对抗性的
    系统会根据设定的比例自动调整对抗性智能体的数量


# 3，训练思路参考
训练策略：
采用双层优化框架:
外层优化信念网络参数
内层优化策略网络参数
使用经验回放缓冲区存储多类型交互数据
考虑使用元学习来加速适应新的对抗模式
实现建议：
设计分阶段训练流程:
第一阶段：预训练合作行为
第二阶段：引入对抗性智能体
第三阶段：联合优化信念和策略
使用注意力机制处理智能体间的交互
实现渐进式的对抗比例调整
评估指标：
信念准确度：预测对抗性智能体的准确率
策略稳健性：面对不同对抗比例的表现
收敛速度：信念网络的学习效率
泛化能力：应对未见过的对抗模式
潜在挑战：
信念空间可能过大，需要有效压缩
多智能体信念的耦合会增加学习难度
对抗性智能体可能有策略性欺骗行为
值分解在高度对抗环境中可能不稳定
改进方向：
引入元控制器动态调整信念更新率
设计分层信念结构处理不同抽象层次
结合因果推理提升信念准确性
使用自适应值分解机制
算法选择：
QMIX作为基础框架
扩展MAVEN处理多模态策略
借鉴RODE处理角色发现
参考MAPPO的策略优化方法
